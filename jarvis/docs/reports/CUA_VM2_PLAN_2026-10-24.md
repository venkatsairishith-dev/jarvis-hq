# The CUA plugin on the second Oracle VM (plan, 2026-10-24)

Owner (2026-10-24): "use my second server jarvis vm2 in Oracle for the CUA plugin", "format and start fresh", and, when asked, **yes: "jarvis vm2" is
`hermes-agent-vm-2`, lift its protection for this, wipe the whole VM disk.** Nothing has been run yet. This is the plan and the order of steps; every destructive step
waits for the owner's yes naming the exact resource (the `oracle-delete` skill and `CLAUDE.md`).

## What the CUA plugin needs

An "Agent PC": a desktop the agents drive, with the owner able to watch and take over. The design already exists and works inside the WSL box on the laptop
(`02_ARCHITECTURE.md`, "The Agent PC is the agents' own computer"): XFCE on display :1, `cua-driver` 0.21.0 (pinned, telemetry off), xdotool and xwd for the gaps
`cua-driver` has on Linux, Firefox from Mozilla's signed apt repository, an unprivileged `jarvis-agent` user with no sudo, a firewall rule for that user, the lab
control service (take control, continue task), and the hub screen. Moving it to VM2 means the laptop is no longer the computer the agents click on, and the agents get
a machine that is always on and that holds none of the owner's real accounts. Code to reuse as is: `jarvis/lab/` (`lab_control.py`, `lab_runner.py`, `screen_tests.py`,
`deploy/*.service`, `check_lab_deploy.py`). Nothing new is written unless a step below cannot be done with them.

## Before anything is wiped (read-only, safe)

1. **Inventory** with the OCI CLI on the laptop (read only): instances, boot volumes, block volumes, VNICs, reserved IPs, backups in the named compartment, with names,
   shapes, states and sizes. Confirms that "jarvis vm2" is exactly one instance and shows its shape (Always Free AMD micro 1/8 OCPU and 1 GB, or Ampere A1 up to 4 OCPU
   and 24 GB for the whole tenancy).
2. **What runs on it today**, so nothing the owner needs is lost: services, cron, Hermes agents, data directories (names and sizes only).
3. **Shape check.** XFCE plus Firefox plus a driver needs about 2 GB of RAM at the least. A 1 GB micro instance cannot do it; an A1 slice (2 OCPU, 12 GB) can, and fits
   the Always Free allowance if the main server leaves room (the total across the tenancy is 4 OCPU and 24 GB).
4. **Cost**: `oci_cost.py` must show $0 before and after.

## Backup (offered, the owner decides)

Boot-volume backup before the wipe. Always Free allows only 5 volume backups in total, so the plan counts the existing ones first and deletes nothing to make room
without asking. Alternative the owner may choose: copy the data directories to the laptop or the vault, then wipe without a volume backup.

## The wipe and rebuild (one named step at a time)

1. The owner removes `hermes-agent-vm-2`'s entries from `D:\jarvis-secrets\protected.json` (only he edits that file; the kernel policy refuses writes to those OCIDs until he does).
2. Rebuild in place: replace the boot volume source with a fresh Ubuntu 24.04 image (same instance, same IP, same subnet; nothing in the shared VCN, subnet or
   security lists is edited). Abort unless exactly one exact-name match.
3. First login over Tailscale only. SSH keys from the owner's existing key; no password login; unattended upgrades on.
4. Install, pinned and checksum-verified like the rest of the lock (`tools/jarvis.lock.json`): XFCE, Xvfb or a real display server, x11vnc or noVNC bound to loopback
   behind Tailscale, `cua-driver`, xdotool, xwd, Firefox (Mozilla apt repo), the unprivileged `jarvis-agent` user and its firewall rule, then `jarvis/lab/deploy/*.service`.
5. `check_lab_deploy.py` and `screen_tests.py` (on-screen test runner with video on failure) on the new machine; the hub shows its screen.
6. Point the CUA plugin at VM2 instead of the WSL box; the WSL box stays as a fallback until VM2 has passed a week of tasks.

## Rules that do not change

Agents on VM2 run as the unprivileged user and can reach the internet only through the egress allow-list; no model key, Telegram token, kernel database or SSH key is
readable by them (measured the same way as on the main server); take control freezes everything the agent user runs; prompt-injection rules for screen text apply
(untrusted flag, no egress tools afterwards). Claude is not a run-time provider here either (D35).
