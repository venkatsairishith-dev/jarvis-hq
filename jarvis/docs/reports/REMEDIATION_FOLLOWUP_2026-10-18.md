### High

**H1. Memory text stayed in the audit log after "forget".**
- Cause: `llm_proxy.py` `memory_action` passed the entry text or query (`target[:80]`) into `Action(...)`; `Action.describe()` in `policy.py` wrote it into the hash-chained audit.
- Fix: for tool `memory`, `describe` now keeps only op, lane, requester and the entry id (`m-xxxxxxxx`); any other target becomes `[text hidden, N characters]`. No hash of the text is kept (a short unsalted hash of a short sentence can be guessed offline). The same reduction applies to `task.create`. Pending approval cards still hold the text they need.
- Paths: `jarvis/kernel/jarvis_kernel/policy.py`, `llm_proxy.py` (`memory_action`), their tests.
- Tests: `jarvis/kernel/tests/test_audit_privacy.py` (7 tests, real HTTP handler, real audit table, a synthetic canary: add, get, list, resolve, render, update, forget by id and by content; then the audit table, owner events, owner state, overview and its audit tail, pending approvals, approval history and the idempotency table are all searched). 5 failures + 1 error on the old code; all pass now. Audit chain, anchors and `verify()` tests unchanged and passing.
- Not fixed: audit rows already written before this change stay in the chain (removing them means rewriting or re-anchoring the chain: owner's call). `ui.type`/`browser.type` text and `repair.edit_file` arguments (≤200 chars, scrubbed) are still audited as the forensic record of PC actions.

**H2. Planner memory reached public providers by default.**
- Cause: `memory_context.py` treated the privacy gateway (`127.0.0.1:48950`) as "private". The gateway forwards to Dahl/Groq and redacted names/places only when `JARVIS_PRIVACY_NAMES=1`. Step goals could then carry memory details to `browser_use`, `computer_use` and `jarvis_bridge delegate_task`.
- Fix: memory goes only to a verified local model (loopback on the port of `JARVIS_LOCAL_LLM`, never the gateway port, exact host match); there is no opt-in to share memory with a public planner. `_llm(local_only=True)` re-checks the endpoint at the call (covers a changed setting, the corrective retry and think steps). Every step of a plan made with memory carries `memory_influenced=True` (persisted, survives resume). `_memory_sink_problem()` runs at the top of `_dispatch`: browser and computer steps run only while the agent slot is still verified local; `jarvis`, `jarvis_bridge:*` and `web_search:*` steps fail visibly with "Needs the owner" unless `MAIN_AGENT_MEMORY_TO_EXTERNAL_STEPS=1` (default off). I chose refusing over redacting because the gateway cannot reliably hide names.
- Also (M4): the memory block sits between `<<<MEMORY-DATA <random tag> begin/end>>>` markers; entries are neutralised (NFKC, control/invisible characters removed, `<` `>` replaced, fences and separator runs defused); disputed, stale and archived entries are excluded and counted; ordering is relevance then last written (event dates are only a clamped fallback).
- Paths: `plugin/plugins/main_agent/{memory_context.py,__init__.py,planner.py,store.py,README.md}`, `tests/test_memory_context.py` (12 new, 29 in the file).
- Tests use synthetic canaries at an HTTP edge (`httpx.MockTransport` for `/browser_use/run`, `/computer_use/run`; recorders for delegate_task and web_search): default public planner, gateway-only URL, gateway down, `JARVIS_PRIVACY_NAMES` unset, local URL, `JARVIS_LOCAL_LLM` pointed at the gateway.
- Deliberate test changes: the old test asserted the gateway was allowed; two other tests were adapted (gateway as planner; outdated-entry wording).
- Consequence you will notice: in code mode, a plan that used memory can no longer delegate to JARVIS or `web_search` by default; it says "Needs the owner".

## 1b. Second pass: screen-text egress, lab verifier, PC-lock race (new in this pass)

### S1. OCR text, page text, window text and file names reaching models (review Low; was "not fixed")
- Cause: with `NEKO_SCREEN_TEXT_TO_MODEL=1` OCR text was only pattern-scrubbed; browser `page` text came back unscrubbed; the troubleshooter's OCR fallback put file/DLL/module names into the report; step results flowed as `inputs` into dependent steps and think steps; error and activity strings could carry the text.
- Fix: one shared helper `plugin/plugins/_shared/screen_text.py` (`release(text, model_url=None)` and the second net `release_safely()`), applied at the source (desktop plugin) and again at the sinks (main_agent). Order: (1) flag off (default) → withheld, even for a local model; (2) secret pass, a private key withholds everything; (3) a **verified local** model (the `memory_allowed` check; the gateway port never counts) gets the text after the secret pass; (4) otherwise paths/file names are reduced to a class and e-mails masked, then the gateway must report `ok`+`ready`+`pii_model` on `/health` and answer `/redact` with `names:true, deep:true` (same contract as research; a test checks both agree on 7 health and 6 answer payloads); (5) any error or anything else → the neutral note "screen text withheld: no verified private model". Never a fallback to raw text.

### S2. Lab verifier's forked-process residual: narrowed, not closed
- Investigation (real forger, container): any secret the verifier knows is readable by code the verifier runs, because both share the agent user.
