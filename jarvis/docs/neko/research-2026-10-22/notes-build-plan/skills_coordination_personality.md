# Skill learning, ChatGPT/Gemini coordination, and personality design for JARVIS (as of Oct 22, 2026)

## (A) Skill learning loop: how to "learn a new task once, store it as a reusable skill", with safety gates

### Takeaway
The de facto skill format in 2026 is the open Agent Skills standard (agentskills.io): a folder holding `SKILL.md` (YAML frontmatter plus Markdown), with optional `scripts/`, `references/` and `assets/`, loaded by progressive disclosure. Hermes Agent and Anthropic both implement it. Hermes writes skills autonomously by default, but it has an opt-in staging/approval mode. Research (AWM, Voyager, ExpeL) shows that reusable workflow/skill memories improve agent success. Marketplace audits, though, show that skills are a major injection and malware vector. JARVIS should therefore keep its existing pattern (propose, then regression gate, then owner promotion) and harden it with sandbox replay, provenance and hash pinning, scoped `allowed-tools`, and content scanning.

### Cited Findings
**Hermes Agent (Nous Research) learning loop**
- Hermes defines skills as "on-demand knowledge documents the agent can load when needed", stored in `~/.hermes/skills/` (the source of truth), with progressive disclosure: "The agent only loads the full skill content when it actually needs it." — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Creation triggers: "The system prompt asks the agent to record a non-trivial workflow with `skill_manage` for future reuse". The three listed cases are (1) a multi-step workflow worth repeating, (2) errors or dead ends where it found a working path, and (3) times the user corrected its approach. A post-session background review can suggest or stage skill changes, and a "curator" runs consolidation passes. `/learn` builds skills from a local directory, a URL, a described workflow, or a large document. — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Format: a directory with `SKILL.md` (YAML frontmatter: `name`, `description`, `version`, `platforms`; a `metadata.hermes` block with `tags`, `category`, conditional activation such as `requires_toolsets`/`fallback_for_toolsets`, and `config`; plus `required_environment_variables` for secrets). Optional subfolders: `references/`, `templates/`, `scripts/`, `assets/`, `examples/`. Hermes declares itself "compatible with the agentskills.io open standard." — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Self-improvement: `skill_manage` supports create, patch, full rewrite, delete and file write/remove, and targeted `patch` edits are preferred. An advisory linter flags things like incident-log narration and oversized bodies, but it "warns but never blocks a write." — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Gating: by default the agent writes skills freely. With `skills.write_approval: true`, writes are "staged instead of committed" under `~/.hermes/pending/skills/` and reviewed with `/skills pending`, `/skills diff`, `/skills approve` and `/skills reject`. Project skills require `hermes skills trust`. Hub installs are scanned for exfiltration, prompt injection, destructive commands and supply-chain signals, and "`--force` does not override a `dangerous` scan verdict". Installed skills are tracked by source plus content hash, and dangerous project-local skills are quarantined. — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)

**Agent Skills open standard (agentskills.io) / Anthropic SKILL.md**
- Required frontmatter: `name` (1–64 chars, lowercase a–z/0–9/hyphens, no leading, trailing or double hyphens, must match the directory name) and `description` (1–1024 chars; "Describes what the skill does and when to use it"). Optional: `license`, `compatibility` (≤500 chars), `metadata` (string→string map), and `allowed-tools` ("Space-separated string of pre-approved tools the skill may use. (Experimental)", e.g. `allowed-tools: Bash(git:*) Bash(jq:*) Read`). — [agentskills.io specification](https://agentskills.io/specification)
- Progressive disclosure: metadata (~100 tokens) loaded at startup for all skills; instructions (<5000 tokens recommended) loaded on activation; resources loaded as needed. "Keep your main SKILL.md under 500 lines." Validate with `skills-ref validate ./my-skill`. — [agentskills.io specification](https://agentskills.io/specification)
- Anthropic's implementation adds: name "Cannot contain XML tags" and "Cannot contain reserved words: 'anthropic', 'claude'". Skills are available on the Claude API (`/v1/skills`, sandboxed container with "No network access"), in Claude Code (`~/.claude/skills/` or `.claude/skills/`, "Full network access") and on claude.ai (zip upload). — [Claude docs: Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)
- Anthropic security guidance: "Use Skills only from trusted sources… a malicious Skill can direct Claude to call tools or run code in ways that don't match the Skill's stated purpose." Its guidance also says: "Skills that fetch data from external URLs pose particular risk… Even trustworthy Skills can be compromised if their external dependencies change over time", and "Treat like installing software." Enterprise orgs can enable "Skill content scanning". — [Claude docs: Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)

**Evidence that learned skills/workflows help**
- Agent Workflow Memory (AWM, ICML 2025) induces reusable workflows from past trajectories and reports "24.6% and 51.1% relative success rate" gains on Mind2Web and WebArena, while "reducing the number of steps". It beats the BrowserGym baseline by 12.0 absolute points and outperforms SteP, which uses human-written workflows, by 7.6% relative. In online mode it generalizes cross-task/website/domain, beating baselines by 8.9–14.0 absolute points. — [AWM paper, arXiv 2409.07429](https://arxiv.org/pdf/2409.07429); [ICML 2025 proceedings](https://proceedings.mlr.press/v267/wang25bx.html)
- Voyager (2023) uses an ever-growing library of executable code skills in Minecraft. Its abstract reports 3.3x more unique items, 2.3x longer distances and up to 15.3x faster tech-tree milestones versus prior SOTA. (Figures recalled from the paper abstract and not re-fetched in this session, so verify them.) — [Voyager, arXiv 2305.16291](https://arxiv.org/abs/2305.16291)
- ExpeL (2023) collects experiences and extracts natural-language "insights" without weight updates, and reports gains on HotpotQA/ALFWorld/WebShop. (Specific numbers were not re-verified in this session.) — [ExpeL, arXiv 2308.10144](https://arxiv.org/abs/2308.10144)
- 2026 follow-on work continues the line, e.g. CONTRAMEM ("Learning Self-Evolving Procedural Memory from Contrasting Multi-Model Trajectories"), which includes an AWM reproduction. — [arXiv 2608.22533](https://arxiv.org/pdf/2608.22533)

**Failure modes / threat evidence**
- Snyk's "ToxicSkills" audit (Feb 2026) scanned 3,984 skills (ClawHub/skills.sh). It found that 13.4% (534) had at least one critical issue (malware distribution, prompt injection, exposed secrets) and that 36.82% (1,467) had at least one flaw of any severity. A follow-up reports 76 confirmed highly malicious skills and a 30+ skill campaign targeting Claude Code/OpenClaw users. Snyk notes that prompt injection in skills is often missed by classical code and malware scanners. (Vendor study.) — [Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub); [Snyk: Agent Skills threat landscape](https://research.snyk.io/blog/agent-skills-threat-landscape/)
- "Towards Secure Agent Skills" (arXiv, Apr 2026) maps the attack surface across a four-phase skill lifecycle: Creation, Distribution, Deployment, Execution. — [arXiv 2604.02837 via EmergentMind](https://www.emergentmind.com/papers/2604.02837)
- Hermes's own linter is advisory only ("never blocks a write"), and auto-writes are on by default. A self-written skill could therefore persist content copied from untrusted web pages or files unless `write_approval` is enabled. — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)

### Inferences
- **Recommended JARVIS loop** ("help me find so-and-so folder"):
  1. Match the request against skill descriptions.
  2. If there is no match, solve it live with existing low-risk tools (read-only search first).
  3. On success, draft a `SKILL.md` in agentskills.io format. Use `metadata` for `jarvis.version`, `jarvis.source_session`, `jarvis.risk_tier` and `jarvis.created_by=agent`, and use a narrow `allowed-tools`.
  4. Stage the draft in a `pending/` area, mirroring Hermes `write_approval`.
  5. Auto-generate one or more bench cases from the live run and replay them in a sandbox, alongside the existing regression suite.
  6. Show the owner a plain-language diff and explanation.
  7. Only the owner promotes. On promotion, record the content hash/signature and version. Any later patch goes back through steps 4–6.
- **Tiered autonomy.** Read-only skills (find a file, summarize a folder) could be "auto-usable after promotion". Skills that write, delete, send or spend should require per-run confirmation even after promotion. This is consistent with the kernel's ban on silent self-modification.
- **Provenance taint.** If a learning session ingested external content (web pages, downloaded files, other models' outputs), mark the draft "tainted" and require extra review. This responds to Anthropic's warning about external URLs and Snyk's injection findings.
- **Drift control.** Pin promoted skills by hash and re-run their bench cases on model upgrades or tool changes. Retire skills whose cases fail instead of letting the agent "patch until green". The Hermes curator/patch loop shows how quickly skills change without such pins.
- **Reuse rather than invent.** Adopting the agentskills.io format keeps JARVIS skills portable to Hermes (on the VM), Claude Code and other compatible agents.

## (B) Coordinating with ChatGPT and Gemini (plus what "Grokbot" likely means)

### Takeaway
Driving the consumer web apps (chatgpt.com, gemini.google.com) with browser automation conflicts with OpenAI's Terms of Use, which ban automated or programmatic extraction of Output and bypassing protective measures. It is also fragile. The legitimate routes are the paid APIs (OpenAI Responses API, Gemini API) for "ask a second model", and MCP in the other direction: expose JARVIS tools as a remote MCP server that ChatGPT (Developer mode) or Gemini CLI can call. Evidence that multi-model consensus helps is mixed. Use it selectively for high-stakes answers, not by default.

### Cited Findings
**Terms on automating the consumer apps**
- The OpenAI Terms of Use (effective Dec 11, 2024 revision) "What you cannot do" list includes: "Automatically or programmatically extract data or Output (defined below)."; "Interfere with or disrupt our Services, including circumvent any rate limits or restrictions or bypass any protective measures or safety mitigations we put on our Services."; and "Use Output to develop models that compete with OpenAI." On accounts: "You may not share your account credentials or make your account available to anyone else" and you "are responsible for all activities that occur under your account." — [OpenAI ToU Dec 11, 2024 (mirror)](https://open.windriver.com/info/uni-license-list/licenses/openai-tou-20241211.html); canonical: [openai.com/policies/row-terms-of-use/revisions/2024-12-11/](https://openai.com/policies/row-terms-of-use/revisions/2024-12-11/). Caveat: openai.com returned HTTP 403 to my fetches, so I could not confirm whether a newer 2025/2026 revision changed the wording. Search results show the same clause on the live terms pages. — [OpenAI Terms of Use](https://openai.com/policies/terms-of-use/)
- Google Terms of Service (Effective July 30, 2026) prohibit "using automated means to access content from any of our services in violation of the machine-readable instructions on our web pages (for example, robots.txt files that disallow crawling, training, or other activities)" and "using AI-generated content from our services to develop machine learning models or related AI technology", along with "hiding or misrepresenting who you are in order to violate these terms". — [Google Terms of Service](https://policies.google.com/terms)
- Google's Generative AI Prohibited Use Policy (last modified Dec 17, 2024) bans "Circumvention of abuse protections or safety filters". — [Google GenAI Prohibited Use Policy](https://policies.google.com/terms/generative-ai/use-policy)

**Legitimate integration paths**
- ChatGPT Developer mode is a full MCP client: "Available to Pro, Plus, Business, Enterprise, and Education accounts on the web. Any tools your connector exposes (including write actions) are available, subject to confirmation settings." — [OpenAI developer docs: ChatGPT Developer mode](https://developers.openai.com/api/docs/guides/developer-mode); [OpenAI Help: Developer mode and full MCP connectors](https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt)
- Tools without a `readOnlyHint` annotation are treated as write-capable, and write actions require user confirmation. ChatGPT connects only to remote HTTPS MCP servers, so a local server needs a tunnel (ngrok, Cloudflare Tunnel, or OpenAI's Secure MCP Tunnel). Workspace admins must enable Developer mode. — [coworker.ai summary](https://coworker.ai/blog/chatgpt-mcp); [Boomi ChatGPT setup](https://help.boomi.com/docs/Atomsphere/Platform/Connect_chatgpt_setup)
- Conflict: Boomi's guide says write-capable MCP is limited to Business/Enterprise/Edu, with Plus/Pro getting read-only custom connectors. OpenAI's developer docs list Plus/Pro with write actions. The two disagree, so treat Plus/Pro write access as unverified. — [Boomi](https://help.boomi.com/docs/Atomsphere/Platform/Connect_chatgpt_setup) vs [OpenAI developer docs](https://developers.openai.com/api/docs/guides/developer-mode)
- Gemini CLI supports MCP servers via `mcpServers` in `~/.gemini/settings.json` (`httpUrl` for remote Streamable HTTP; `command`/`args` for stdio), OAuth, `/mcp` to inspect connections, and `includeTools`/`excludeTools` filters. — [Tembo: Gemini CLI MCP (2026)](https://www.tembo.io/blog/gemini-cli-mcp)
- Single-source, unverified claim: Tembo says Google stopped serving Gemini CLI on free/AI Pro/Ultra tiers, moved individuals to a closed-source "Antigravity CLI" (`agy`), and requires a paid Gemini API key or enterprise license for the open-source CLI. Verify this with Google before relying on it. — [Tembo](https://www.tembo.io/blog/gemini-cli-mcp)
- I found no source describing custom MCP servers in the consumer Gemini app. — (search returned none; see Gaps)

**Multi-model "second opinion" evidence**
- Positive but small: a 2026 learned-consensus model beat the strongest single LLM by 4.6 points on compact subsets of four benchmarks ([arXiv 2601.07245](https://www.arxiv.org/pdf/2601.07245)). A 2024 preprint reports precision rising from 73.1% to 95.6% with three models, but on only 78 cases ([arXiv 2411.06535](https://arxiv.org/pdf/2411.06535v1)).
- Counter-evidence: DeliberationBench ("When Do More Voices Hurt?") argues that prior work lacks strong selection baselines, and finds that picking the best single model can beat ensembles with flawed aggregation. — [arXiv 2601.08835](https://arxiv.org/html/2601.08835v1)
- Practitioner costs: roughly 2–4x inference cost, plus correlated errors across models trained on similar data. — [tianpan.co: Multi-Model Consensus (May 2026)](https://tianpan.co/blog/2026-05-05-multi-model-consensus-architecture-llm-sign-off)

**What "Grokbot / Grok Bot" likely means**
- "Grok Bot" appears to be a 2026 xAI product linked from x.ai/bot. It is a desktop app (Mac), with a mobile app, that runs "a team of bots on a computer that is not yours", each bot operating its own remote desktop. A "chief of staff" bot delegates to specialist bots (inbox triage, LinkedIn posting, GitHub issues, calendar), and there is a Plugins section (Gmail, Calendar, Drive, Notion, Slack, Playwright, GitHub, X). The source is a blog post dated Aug 14, 2026 ("just dropped"), with free-trial usage noted and no pricing given. — [debbie.codes: How to get started with Grok Bot](https://debbie.codes/blog/how-to-get-started-with-grok-bot); also [Analytics Vidhya: Getting Started with Grok Bot](https://www.analyticsvidhya.com/?p=257374)
- Open-source "grokbot" items are unofficial: `b-nnett/grok-bot-0.18-reconstructed` (claimed reconstruction from shipped source maps, unverified), OPENBOT (Apache-2.0 Rust/Tauri "open-source alternative"), and `awesome-grok-bot` lists of skills/plugins/MCP servers. None of these should be confused with the March 2024 Apache-2.0 release of Grok-1 model weights. — [chatgate.ai: OPENBOT](https://chatgate.ai/post/openbot-2); [mezha.ua on Grok-1 open weights](https://mezha.ua/en/2024/03/18/elon-musk-s-grok-chatbot-becomes-open-source-and-is-already-available-on-github/)

### Inferences
- **Recommended method: "APIs out, MCP in".**
  - **(1) JARVIS asks ChatGPT/Gemini.** Call the OpenAI Responses API and Gemini API with the owner's own API keys. This needs separate pay-as-you-go billing, because consumer subscriptions do not include API access. Log each external call and label the external answer in the UI ("Gemini says…").
  - **(2) ChatGPT/Gemini use JARVIS.** Expose a small, read-only-first remote MCP server (with `readOnlyHint` set) behind auth and a tunnel. The owner can then call JARVIS tools from inside ChatGPT Developer mode or Gemini CLI. Any write tool must stay behind JARVIS's own confirmation gate, independent of ChatGPT's.
  - **(3) Avoid Playwright/CUA automation of chatgpt.com or gemini.google.com.** It plausibly violates OpenAI's "programmatically extract… Output" clause and risks the owner's account. It is also brittle, since the UIs, bot checks and CAPTCHAs change often.
  - Since N.E.K.O already has computer-use (`computer_use.py`), add an explicit kernel denylist for those domains.
- Treat other models' answers as untrusted input, not instructions. They should never be written into skills or memory without the same provenance tagging and review.
- Use the second opinion selectively. Reasonable triggers are high-stakes factual questions, disagreement detection, or explicit owner request. JARVIS should present disagreements rather than average them, given DeliberationBench's caution.
- If the owner said "Grokbot", the likely meaning is xAI's 2026 Grok Bot multi-bot desktop/remote-computer product, as a reference design for a chief-of-staff bot delegating to specialists. The owner might also mean simply "Grok" (xAI's chatbot/API). Confirm with the owner.

## (C) Personality and explanation design for a human-like, explanatory assistant

### Takeaway
Keep a stable, durable identity file (like Hermes `SOUL.md` / N.E.K.O character card) focused on voice, honesty and disagreement norms, separate from task knowledge. Make anti-sycophancy an explicit, tested property: OpenAI's GPT-4o rollback shows that "agreeable" tuning can ship by accident. Explanations and progress narration should come from real execution events, not generated filler.

### Cited Findings
- N.E.K.O (Networked Emotional Knowledging Organism) is an open-source AI companion. Persona is edited at `/character_card_manager` (default companion "YUI"). It has basic persona items (the README advises keeping them few), an advanced `system_prompt` (changing it is not recommended), voice cloning (~5 s clean sample), Live2D/VRM/MMD models, export as settings-only or full card, and Steam Workshop sharing. — [N.E.K.O GitHub README](https://github.com/Project-N-E-K-O/N.E.K.O)
- N.E.K.O memory has five dimensions: "工作记忆 / 近期记忆 / 事实记忆 / 反思记忆 / 人格记忆" (working/recent/fact/reflection/persona). `/memory_browser` lets the user review and proofread memories and summaries, and memory is synced across apps. The agent "可操作浏览器与电脑，调用 CUA / OpenClaw A2A / 插件完成任务" (can operate the browser/computer via CUA, OpenClaw A2A and plugins), and `brain/` includes `computer_use.py`, `browser_use_adapter.py`, `openclaw_adapter.py` and `task_executor.py`. — [N.E.K.O GitHub README](https://github.com/Project-N-E-K-O/N.E.K.O)
- Hermes `SOUL.md` is the "primary identity file" (`~/.hermes/SOUL.md`). It is injected into slot #1 of the system prompt, "passes through prompt-injection scanning and truncation", and is not loaded from the CWD. The guidance says to keep it to durable voice (tone, directness, handling uncertainty and disagreement) and to put project facts in `AGENTS.md`: "if it should follow you everywhere, it belongs in SOUL.md." The example SOUL lists "Sycophancy" and "Hype language" as things to avoid, and includes "Push back when something is a bad idea." Session presets (`/personality` teacher, concise, etc.) are overlays. — [Hermes docs: Personality/SOUL.md](https://hermes-agent.nousresearch.com/docs/user-guide/features/personality)
- OpenAI rolled back an April 2025 GPT-4o update for being "overly flattering or agreeable". It said it would treat model-behavior issues as launch-blocking, admitted its behavior testing was less formalized than its tracking of safety risks, and noted people use ChatGPT for "deeply personal advice" more than expected. — [OpenAI: Sycophancy in GPT-4o](https://openai.com/index/sycophancy-in-gpt-4o/)
- Anthropic's "persona vectors" work identifies activation directions for traits such as sycophancy, which can be subtracted to steer away from them or used during training as a "vaccine". IEEE Spectrum also reports that prompting "You are an independent thinker" rather than "helpful assistant" reduced sycophancy. (Secondary source; I did not fetch Anthropic's primary paper.) — [IEEE Spectrum: AI sycophancy](https://spectrum.ieee.org/ai-sycophancy)

### Inferences
- **Map onto N.E.K.O.** Put JARVIS's durable identity in the character card's basic persona items (few, durable traits) and keep the advanced `system_prompt` kernel-owned. Store the owner's preferences in fact/persona memory, and expose `/memory_browser`-style review so the owner can correct what JARVIS "believes". Treat the persona file like core code: changes are proposed and owner-approved, never self-edited. This matches the kernel rule and Hermes's practice of scanning SOUL.md for injection.
- **Honest narration contract.** Status lines such as "searching D:\Projects…, found 3 matches" must be rendered from actual tool-call events (start, args summary, result, error), never from model-predicted progress. When a step fails, say so plainly and explain what will be tried next. "Explanatory" mode should tell the owner *why* a method was chosen and *what was learned*, e.g. "I saved this as a skill draft; here's what it does; approve?"
- **Anti-sycophancy as a regression property.** Add bench cases where the owner proposes something wrong or risky and JARVIS must disagree politely. Run them whenever the persona or model changes, mirroring OpenAI's lesson to make behavior issues launch-blocking.
- **Personality never overrides safety gates.** A warm or playful tone (N.E.K.O companion style) is fine, but the persona must not soften confirmations, hide uncertainty, or claim feelings and capabilities it doesn't have.
